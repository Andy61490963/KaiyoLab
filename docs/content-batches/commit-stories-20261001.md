## 執行與保護

正常啟動在既有 migration 後呼叫 `seedCommitStories`。僅 `SITE_URL` 的來源精確等於 `https://kaiyo.zeabur.app`、根路徑且已完成站長初始化時執行。其他來源不查詢資料庫；帳號復原維護模式不執行本批。

單一交易依序取得既有 migration lock 620214 與 content lock 620215。沿用現有 `schema_migrations` 的一列 `content/commit-stories-20261001` 作為批次完成標記，沒有新增資料表或欄位。

若同標題已匯入，保留該筆包含垃圾桶的現況，不覆蓋、不復活；固定 ID 已屬於另一份內容則整批拒絕。新文章追加到順位尾端，網址若與現行或歷史網址重複，選擇 `-story-1` 等新網址。共用既有分類／標籤名稱，新的分類／標籤以隨機後綴避免網址衝突。

每篇寫入後核對正文完全一致且公開快照為 NULL，並保存初始草稿歷史。全部完成才提交批次標記。任一步失敗回滾整批；重啟讀取同批標記後不重建，不覆寫後續人工編輯。提交結果不明時讓啟動失敗，下一次連線以批次標記判斷，不盲目重送。

## 部署驗證

只有啟動程序收到已提交結果後才建立內部部署回執。既有 `/api/health` 僅回傳固定批次代稱、完成狀態和首次建立／保留數量，不回傳文章 ID、標題、正文、設定或憑證。重新啟動的 `already-applied` 代表本批曾完成，不宣稱使用者之後未修改或刪除文章。

正式部署驗證除了核對 Git revision、公開頁面可讀與匿名管理 API 401，也核對本批回執，並在 Actions 紀錄輸出固定格式筆數。
