# LAB 工程實驗

LAB 包含五個可獨立開啟的實驗與原有 CMS 作品列表，使用現有 Astro、React、TypeScript、SVG、Canvas 與 Web Worker，不增加動畫、圖表或數學套件

## 實驗與模組責任

| 路由                    | 可操作內容                                     | 工程核心                                                            |
| ----------------------- | ---------------------------------------------- | ------------------------------------------------------------------- |
| `/lab/market-replay`    | 下單、撤單、情境、逐事件回放、壓力模式         | 整數 tick、價格時間優先 FIFO、事件紀錄與 checkpoint、同步圖表及指標 |
| `/lab/risk-simulator`   | 配置比例、相關矩陣、一萬條一年路徑、取消與重算 | Cholesky、GBM、VaR/CVaR、回撤、離散前緣、Worker 批次與過期結果隔離  |
| `/lab/liquidity-story`  | 捲動敘事、滑桿、章節、指標攝影機               | 單一確定性時間模型、解析阻尼、深度分層、反向時間                    |
| `/lab/kinetic-carousel` | 觸控拖曳、鍵盤、無限循環、播放與暫停           | 無界位置、週期映射、釋放速度、慣性投射、解析彈簧                    |
| `/lab/flow-field`       | 種子、吸引與排斥、速率、單步、重設             | 無散度 curl 場、固定步長積分、緩衝區重用、自適應粒子數              |

模型位於 `src/lib/lab`，React 元件只負責互動與繪製，Astro 路由共用 `LabLayout`，每個路由僅啟用自己的 island，文章與其他公開頁不載入實驗模組

`useLabEnvironment` 集中讀取語言、主題、減少動態與分頁可見性，每個元件另管理自己的可視區、動畫、指標與清理生命週期

## 模型界線

金融實驗使用可重現的模擬資料，不存取真實交易或投資帳戶

撮合核心用整數價格與數量，未成交市價餘量取消，改變回放位置後新增訂單會建立新的未來，不把舊情境繼續套用在不同狀態

回放 1× 表示每秒前進 25 筆事件，不代表真實市場的每秒成交速度；2×、5×、10× 加速同一事件序列，每 64 筆保存 checkpoint，倒轉最多重算 63 筆事件

壓力模式是最多 50,000 次操作的本機核心測量，每批最多 128 次或約 4ms 便讓出主執行緒，不將瀏覽器結果宣稱為交易所吞吐量

風險模型以假設參數描述三類資產的一年買入持有，不再平衡；前緣為非負配置網格的近似，畫面與技術筆記標示模型假設與限制

每條路徑包含 252 個交易日，使用固定種子、Box–Muller 常態樣本、Cholesky 相關化與 GBM 對數步進；解析期望與標準差同樣以一年終值衡量，避免與蒙地卡羅輸出混用不同時間尺度

10,000 條路徑只保留每 7 個交易日的 37 個快照、12 條完整展示路徑及終值／回撤，主要 typed arrays 約 3MB；前緣遍歷 2% 權重網格的 1,326 種配置，取非支配包絡，不是連續最佳解

模型參考：[相關價格路徑](https://www.mathworks.com/help/finance/portsim.html)、[GBM 模擬](https://www.mathworks.com/help/finance/example-simulating-equity-prices.html)、[均值變異數模型](https://www.mathworks.com/help/finance/portfolio-optimization-theory-mv.html)、[Expected Shortfall](https://www.mathworks.com/help/risk/overview-of-expected-shortfall-backtesting.html)

事件敘事是虛構的價格、深度與暫停模型，不代表特定交易所熔斷規則

## 效能與生命週期

- 金融核心運算與畫面分離，Canvas / SVG 圖表避免把每個資料點變成 React 狀態
- Worker 分批回報進度，使用執行識別碼隔離過期訊息，取消與卸載時終止
- 輪播位置使用 transform，依速度小幅調整 blur，手機降低模糊量；Canvas 像素比上限為 2
- 連續動畫以實際經過時間或固定積分步長推進，避免不同更新率改變結果
- 閒置攝影機停止 requestAnimationFrame，分頁隱藏與可視區離開停止背景工作
- 減少動態模式保留核心控制，改用直接切換與單步，不鎖住資料操作
- 所有 ResizeObserver、IntersectionObserver、媒體查詢、事件監聽、timer 與動畫均有對稱清理

瀏覽器行為依據：[requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)、[Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)、[Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)、[Worker 終止](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate)、[ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)

## 實際效能量測

2026-09-30 在本機正式 SSR 建置、專用無介面 Chromium、1440×1000 與未降速 CPU 下量測，動畫實驗取約 3.2 秒互動區間，風險實驗量測當次運算完成所需區間

| 實驗               | 主執行緒 RAF 頻率 | 計時器延遲 p95 | 超過 50ms 的工作 | 導覽後 CLS | 路由入口 gzip |
| ------------------ | ----------------: | -------------: | ---------------: | ---------: | ------------: |
| 慣性檔案庫         |           約 60Hz |          3.4ms |                0 |     0.0025 |         4.0KB |
| 看不見的流場       |           約 60Hz |          1.2ms |                0 |     0.0001 |         4.9KB |
| 流動性消失的 60 秒 |           約 60Hz |          1.1ms |                0 |     0.0005 |         4.7KB |
| 市場微結構         |           約 60Hz |          0.9ms |                0 |     0.0434 |        10.5KB |
| 風險的形狀         |           約 60Hz |          0.8ms |                0 |     0.0002 |         8.5KB |

RAF 探針衡量主執行緒排程，不等於實體裝置 GPU 合成 FPS；這些數字不代表低階手機保證，入口大小另需加計約 65KB gzip 的共用 React runtime

- 一萬條路徑運算期間，主執行緒計時器最大延遲為 1.0ms
- 快速連續變更種子後，只呈現最後一次結果；同種子重算的 VaR／CVaR 相同
- 離開風險頁後 Worker 全部銷毀，追蹤到的 5 次建立與 5 次銷毀相符
- 流場離開可視區前後均停在第 399 步，沒有持續積分
- 關閉 BFCache 後進行 10 次路由往返並明確觸發 GC，DOM 維持 271 個節點、19 個 listener 與 1 個 document，heap 從 1,120,380 變為 1,115,944 bytes，未觀察到遞增趨勢
- 文章列表與實際文章均回應 200，網路記錄中沒有 LAB 模組

短時間量測與 GC 樣本只能指出當次是否有成長，不能證明所有瀏覽器均無記憶體洩漏；程式審查另核對 observer、timer、RAF、pointer capture 與 Worker 的清理

## 六輪審查與修正

1. **功能**：實際操作撮合、部分成交、撤單、回放倒轉、情境切換、模擬取消及失敗重試；補上表單 select 明確名稱，讓鍵盤與讀屏定位一致
2. **動畫**：修正敘事第 44 秒章節邊界與恢復時的微小跳點，確認快速捲動反向時間、無限輪播與 Esc 取消；減少動態時不再持續要求空白動畫幀
3. **程式**：由獨立審查檢查數量不變式、Worker 執行識別碼、純運算模組與清理；圖片在 React 掛載前就失敗時，改由掛載檢查接住錯誤並提供重試
4. **效能**：實測主執行緒回應、長工作、CLS、離頁釋放與文章載入隔離；使用有界重播、typed arrays、進度節流、可見性暫停與固定步長
5. **技術深度**：撮合以真實 FIFO 與事件紀錄驅動畫面；風險使用相關路徑與一致的終值統計；輪播使用解析彈簧，流場使用勢函數 curl，沒有用圖表套件替代模型
6. **視覺**：檢查七種指定寬度、明暗及中英文，保留奶油白、炭灰與莓紅；放大手機圖表刻度與敘事章節文字，調整小螢幕控制間距

最後操作巡檢另修正三個邊界：流場鍵盤作用力可保留到單步按鈕，離開實驗區或 Esc 才解除；Canvas 不可用時敘事切換手動控制；流場背景改為每 0.1 秒淡出，避免逐幀低 alpha 合成的 8-bit 量化累積成深藍，粒子仍每 1/120 秒積分與繪製

對應故障測試比較同種子的真實 Canvas 軌跡、注入 Canvas 初始化失敗，以及將實際淡出參數重複合成 2,400 次，驗證背景仍維持品牌色

## 重現驗證

在已設定本機開發資料庫的環境執行，E2E 使用獨立測試資料，不應指向正式網站

```bash
npm run check
npm test -- --maxWorkers=2
npm run test:integration
npm run build
npm run test:e2e
```

本機第一次完整單元測試遇到既有 Mermaid 隔離解析超過 8 秒，單獨重跑及限制兩個 worker 的整套重跑均通過；未重現為產品邏輯錯誤，產品的逾時限制保持原值

LAB 新增測試在 `tests/lab-*.test.ts` 與 `tests/e2e/lab-*.spec.ts`，瀏覽器測試包含 1920、1440、1280、1024、768、430、390px、明暗／中英文、觸控、鍵盤、減少動態、錯誤注入與返回頁面

本機驗證結果：199 項單元測試、81 項 PostgreSQL 整合測試全部通過；完整 96 項瀏覽器流程通過，最後三項邊界修正後再跑 LAB 的 21 項流程亦全部通過，型別檢查沒有錯誤與警告，正式建置成功

六張輪播圖為專案內原創數學 SVG，固定 720×900 比例，沒有外部圖片依賴；實際介面截圖收錄在 `docs/screenshots/lab-*.png`
